## What P1.2 is

An **alternative landing view** for a deck: a single read-only chronological **feed**
("Huddle feed") that composes data we already store — version events, comments, requested
slides (stubs), removal flags — with the deck demoted to a side **peek**. Gated on per-account
opt-in (design partners); everyone else still lands on the deck viewer. Instrumented so we can
measure feed-vs-deck usage (the Phase-1 gate evidence). **Read-only** — you participate by
opening the deck and using the existing controls; your feedback shows back up in the feed.

**Status: 🔵 in progress, committed to `main` (deploys via Vercel). Not yet validated with
partners; analytics not yet recording (no key); one migration not yet run.**

## How to run / test

- Dev: `npm run dev --prefix web` → http://localhost:3000.
- **You must be signed in as a design partner** to see the feed + avatars (comments/identities
  load only for signed-in viewers). Partner allowlist = env var **`FEED_PARTNER_EMAILS`**
  (comma-separated) in `web/.env.local` (local) and Vercel (prod). A listed account opening
  `/viewer?id=…` lands on the feed; everyone else on the deck.
- URL overrides (always win): `?view=feed` forces the feed, `?view=deck` forces the deck,
  `?view=classic`/`?view=floating` keep their existing meaning.

  Benchmark"), owner **greg@getpinpoint.com**; collaborators **greg.manzanera@gmail.com** +

## Outstanding work to complete the experience (prioritised)

**A. The "focus on what's unaddressed" greyscale treatment — ✅ DONE (2026-06-17).**
Presentation-only; no data/logic change. As soon as a newer version exists, everything in the
rounds **before the latest version** desaturates to **grey** (version messages, their thumbnail
strips, and any **resolved/addressed/dismissed** items), so the history reads as "settled"; the
exceptions stay in **full colour** so live threads pop. Implemented as:
   - **Version messages** before the current round desaturate via `filter: grayscale(1)
     opacity(.65)` on the `VersionSpineEvent` root (driven off the existing `isCurrent` —
     `muted = !isCurrent`). The current version keeps its model-logo mark / purple vN; hover clears it.
   - **Feed item cards** take a new `muted` prop (`FeedItemCard.tsx`), computed in `DeckFeed`:
     `muted = !round.isCurrent && (item.addressedIn != null || dismissed)`. So **unaddressed/
     unresolved** items (comments AND stubs AND flags) keep colour; the current round never mutes.
   - Same CSS on both (`[filter:grayscale(1)_opacity(0.65)] hover:[filter:none]`) → one filter
     greys the avatar/chips/thumbnail/text together, and **hover or selection** returns it to
     colour (`muted && !selected` gate on the card).
   - **Verified:** tsc clean; computed styles confirm v1–v(N−1) = `grayscale(1) opacity(0.65)`,
     current = `none`; the `:hover→filter:none` rule compiled. The item-card path shares the
     identical classes (compiled-CSS confirmed) but the *signed-in* contrast (an addressed
     comment greys while an unaddressed one stays blue) wasn't visually re-checked this session —
     no partner sign-in available locally. Worth a 30-sec look on the next signed-in pass.

**B. Comment "addressed" is INFERRED, not a hard flag.** Comments have no `resolved_at` column, so
`buildVersionSpine` marks a comment "addressed in v(N+1)" simply because a later version was
published after it (the read-only twin of resolution). It's optimistic. If/when comment
resolution becomes real (Phase 3 messages model, or a `comments.resolved_at` column), replace the
inferred logic in `feed-items.ts` (`buildVersionSpine`, the `item.kind === "comment"` block).

**C. Mobile pass (owed).** The feed is desktop-first: the deck peek hides `< lg` (no bottom
sheet); cards stack and the round indent shrinks, but there's no mobile-tuned layout. Fold into
P1.1 **Stage E (mobile)**, which is parked for the deck viewer too.

**D. Floating "scroll to latest ⌄" button** (in the claude.ai reference, bottom-centre) — not
